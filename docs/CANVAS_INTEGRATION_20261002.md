# 自由画布接入与高级工具缺口

日期：2026-10-02；2026-10-03 补充实际剪辑衔接验收。本轮按用户要求暂停参考视频复刻，接入本机已有的镜场画布。继续使用原文旅工作树，没有重置、删除或重新安装。

## 使用入口

工作台导航菜单 → **自由画布**，或访问 `/canvas?project=当前作品编号`。

1. **带入作品资料**：脚本、分镜文字、连线和选中的本机图片／视频／音频进入此作品独立的镜场工程。默认勾选「同时建立剪辑镜头」，将分镜顺序、实际时长和脚本旁白带入原生分镜／剪辑界面。
2. **画布内编辑**：保留镜场原有的节点、工作流、分镜、剪辑和资产界面；保存由原生修订检查负责。
3. **取回画布产物**：仅复制勾选的当前画布媒体到文旅项目，随后可直接点击「去后期制作使用」。也可取回导入的素材副本；它们不会因此被描述为新生成的作品。
4. 未选择作品时，可以独立打开镜场。服务没有启动时，点击「启动画布」启动已有本机 Node 服务，不安装新软件。

网页进入和刷新不创建工程、不上传素材、不运行生成。选中作品后明确打开／带入，才建立画布关联。脚本或分镜改动以新的节点版本追加；重复带入不复制同一批节点，也不覆盖用户在画布中的编辑。

剪辑镜头按源作品和分镜编号只建立一次。再次带入时，已修改的时长、对白、素材选择和镜头顺序保持原样；源计划更新后需要在画布内主动调整已有镜头。只绑定本次勾选的文件，源素材清单里的明确绑定优先；没有明确绑定时，唯一同编号的视频优先于对应分镜图。匹配不明确或所选文件不足时，镜头留空并提示在「分镜」里选择画面。图片按镜头时长显示；图像内容与旁白的语义一致性仍需人审。

## 本轮实现

- `web_api/canvas_bridge.py` 提供只使用固定本机回环地址的交换接口；关联指针保存在 `.runtime/canvas-bridge/links/`。
- `/canvas` 嵌入真实镜场界面，没有另写一套假画布。现有脚本、分镜和素材通过原生 API 保存；修订冲突只重新合并追加内容，不重复上传或生成。
- 图片按实际文件头判断格式，兼容既有 JPEG 字节以 `.png` 文件名保存的成果，原件不改名。无法识别的图片单独跳过，其他媒体仍可选择。
- 文件大小、实际字节和 SHA-256 校验一致后，才将副本作为可用素材。中断接收记录保留，不自动重交。
- 取回媒体位于 `assets/canvas/<镜场工程编号>/`，来源清单是 `artifacts/canvas_manifest.json`。工作台实际素材列表已识别这些文件；不改已确认的原分镜、素材绑定或制作检查点。
- 相同输出再次取回复用现有副本；已被修改的副本保留并明确拒绝覆盖。只允许当前关联画布的媒体，不能读取其他工程或任意外部地址。
- 单份媒体最大 4 GB，每次最多选择 64 份；选择窗口明确显示大小。响应不含模型密钥。
- 修复镜场 `server.mjs` 中三个实际存在但未提供的公共模块路由：`native-prompt-core.js`、`native-loop-core.js`、`source-index-core.js`。此前这些模块 404 导致原生主界面空白；未覆盖镜场其他代码。镜场在另一对话中并发升级，最终健康版本为 **0.94.0**，该升级成果保持。

## 画布自身仍在升级的范围

本轮完成工作台与已有画布的实际资料交换和剪辑镜头衔接，不能宣称镜场已经完整复刻另一套画布。其 0.94 文档仍记录嵌套／分支／反馈循环、随机种子策略的完整源语义、真实平台／GPU及跨设备验收等缺口。独立整库备份的后端、界面和测试正在另一对话中升级，本轮保留这些更新；源码存在不作为该备份已上线或完整验收的证明。来源是镜场 `docs/NATIVE-DIRECTOR-PROGRESS-2026-10-02.md` 及本机新增备份文件；其历史 789 项本地合成／模拟接口测试不作为本轮真实云端验收。

已确认脚本和镜头不会自动被画布的任意编辑反向覆盖。画布生成先执行原有模型／运行授权，再明确加入当前画布，最后选择取回；全自动双向同步和外部生成质量不在本轮已通过范围内。
