日期：2026-10-02。沿用现有工作树、OpenMontage 制作室和 DeepSeek 试用配置；没有新建参考复刻专页，没有删除或重置现有项目。

## 页面操作

入口仍为「工具与设置 → OpenMontage 制作室 → AI 导演」。

- 「检查导演条件」返回分组清单：导演模型、数据传输与预算、制作工具；选择 Hypit 时增加运行环境和参考视频。需要补齐的模型、预算或视频可直接点击「去设置 / 选择视频」。
- 参数改变立即撤销开始确认，使旧检查结果失效；检查过程中改变参数，较晚返回的旧结果也不能成为当前条件通过的依据。再次检查失败时移除旧的通过状态。
- 没有检查的工具明确写「尚未检查」；存在依赖缺口的工具写「步骤中核对」。通过表示可以开始导演规划，具体工具的账号、输入、费用与工程仍须在实际步骤预检，不承诺成片已经完成。
- 检查范围和注意事项按需展开；清单已有的缺项不再在下方重复显示长提示。桌面与手机使用同一套控件。
- 开始时显示正在建立任务，并暂停重复提交；收到任务编号后展示实际状态，清除开始勾选，不把排队或运行当成制作完成。

## 回执丢失与安全重试

每次明确开始有一个随机提交编号。服务在建立工程和派发模型任务前，先保存编号与原参数摘要；相同编号和相同参数只返回原任务。参数变化不能借用旧编号。并发重复 POST、任务已结束、服务重启，都不会因此重发模型请求。

网页只对已经确认的提交在本机浏览器的 **sessionStorage（当前浏览窗口的临时存储）** 保留参数；不保存服务密钥。已确认任务或明确未建立的任务清除此记录。存储不可用时当前页面仍保留核对信息，并提示保持页面打开。

如果 HTTP 回执未收到：

1. 保留已提交的需求与预算，暂时锁定新提交；可以展开查看本次参数。
2. 「核对本次提交」只发本机 GET，查到任务就恢复原任务记录，不发模型请求。
3. 尚未查到记录时，才提供「重试同一次提交」。由用户点击，沿用同一编号、参数和原确认；后端仍去重，避免较慢的原 POST 随后返回时产生两项任务。
4. 工程建立中断、记录损坏或核对服务不可用，继续保留未知状态，不悄悄换编号新建。完整的失败任务也不自动重新制作或重新计费。

这是提交回执恢复，不是把失败、预算耗尽或服务重启中断的制作自动续跑。阶段确认、模型预算预留、图片发送确认与 Hypit 源码/计划确认保持原有约束。

新增只读接口：`GET /model-api/montage/director/requests/{client_request_id}?project_id=…`。已接受的网页提交在项目 `analysis/montage/director-requests/` 保存索引；旧客户端不传编号的行为保持兼容。所有路径与编号仍按项目范围校验。
