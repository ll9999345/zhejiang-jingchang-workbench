## 实际缺口

原生待生成参考用 `expectedCount` 和可选 `producerIndices` 表示生产者的原输出序号。旧记录没有显式序号时沿用 `0..count-1` 的确认范围；循环切片却可能需要原生产者第 3、4 份。不能把缺字段直接补成切片的新序号，也不能等上游新生成以后才发现范围不一致。

本轮先补清楚的只读核对和续跑前检查，**尚未完成“明确重新确认以后继续同一旧任务”的操作闭环**。整体发布门槛仍未通过，不把新增保护当成全功能恢复。

## 已实现

- `lib/legacy-native-input-audit.mjs` 对未提交、未完成的旧 API 整组参考，使用保存的任务快照、原接口选择、循环上下文及分支恢复结果，检查实际需要的生产序号是否在原确认范围内。
- 首批索引仍相同、原确认范围足够大、已有明确原序号、已完成步骤和带原子任务编号的步骤不整类阻断。已有子任务继续使用原查询路径；没有为它重新创建生成请求。
- 区分 `compatible`、`requires_confirmation` 和 `unverifiable`。缺快照、多条旧选择无法唯一对应、逐轮映射尚不能可靠重建时明确不能确认。没有猜测新增授权。
- `canvasRunner.resume` 在恢复子任务、读取本次认证和写入运行状态前核对；有歧义时返回 409 / `NATIVE_LEGACY_INPUT_REVIEW_REQUIRED`。服务只转发这一明确新增代码，不透传任意错误码。
- 现有任务 GET/列表的公开投影附带核对说明和 `canResume=false`，**不修改原任务、步骤或项目快照**。没有新增任务接口。确认字段、生产者范围和最终真实输出仍由原解析器检查。
- 任务窗口显示人类序号，例如“旧确认第 1、2 份；快照需要第 3、4 份”。保留查看记录、原结果预览及取回已完成步骤的入口。没有增加生成、上传或自动刷新动作。
- 无旧待核对字段的任务不复制/散列整份快照；同次核对共用一份保护性副本，减少大任务列表的不必要开销。

`fingerprint` 目前只标记本次观察的任务状态，包含运行字段；**不是确认令牌**。下一阶段实现审批时必须改用稳定的选择/命令范围证据，并对确认时的实际任务重新核对，不能直接把此字段当作恢复授权。
