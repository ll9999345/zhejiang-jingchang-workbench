# 镜场0.99.22 · 成员编辑、跨组调整与拖入归属

本轮延续0.99.21的输入组创建，补齐普通group/promptGroup已有成员的增删与名称编辑，以及普通节点拖入/移出时的自动归属。实现于10月22日起，最终检查与交付日期为2026-10-23。整体参考项目整合仍未完成。

## 使用方法

1. 选中普通输入组，打开右侧检查器，点「编辑成员」。勾选成员、修改组名，先「检查成员修改」，核对涉及的其他组、连线和素材字段后再保存。此过程仅修改本机画布，不启动模型。
2. 图文组接受图片与文字；提示词组只接收文字。加入同类型新组，会从原同类型组移出。同一文字可同时属于一个图文组及一个提示词组，和固定源一致。原有特殊成员可保留或移出，不能新增不适用类型。
3. 拖动普通图片或文字节点，松开时按节点中心是否在组框内决定归属；含边界，重叠时取工程节点数组中第一个对应类型组。拖出后原节点、素材文件仍保留。组的范围取实际显示尺寸。
4. 拖整个组时成员一起移动，按固定源endDrag规则跳过重新归属。Alt拖动普通节点复制时，新节点、完整草稿和归属一次保存，没有只保存半份副本的中间版本。
5. 成员修改及一次拖动分别可用一次撤销/重做恢复。保存时若发生版本冲突，保留后来的本机编辑并提示检查；不会自动重复提交。页面没收到成功回应时，读取原本机回执核对是否已保存，不把不确定结果当成成功。
6. 明确选中的单个图片字段继续指向原生产节点/原序号：移走前一张图时调整序号；移走被选图片时改为原图片生产节点，并补回必要直连。整组参考仍跟随组成员，空组参考从列表移出。H3全局/片段、云绑定及LTX片段同样保留明确选择。
7. 「编辑成员」只改变归属；「移出组与成员」会把组及成员节点一起移出画布，仍保留素材文件。两者在界面中有明确说明。

## 设计与接口

`lib/input-group-membership.mjs`独立计算完整计划，核对工程版本、成员类型、语义环、容量及原字段来源；整体校验后才落盘。保留已有显式成员引用、无关消息/任务及原素材。原生输入次序按既有数据流展开，源成员附加信息不丢弃。

- POST `/api/projects/:id/input-groups/preview`：manual请求含requestId、revision、groupId、memberIds、title；返回changed、planHash和effects，不保存。
- POST `/api/projects/:id/input-groups/apply`：相同manual请求加planHash；锁定工程后重算，只有完全一致才保存。同一requestId并发重复确认只写一个修订。
- POST `/api/projects/:id/input-groups/reconcile`：drag请求含requestId、revision、draft、movedIds及实际rects；在服务端重算归属，位置、新副本及已有待保存编辑作为一份工程落盘。
- `settings.inputGroupEditReceipt`只保存本机修改的请求/计划散列及结果修订、统计，不是生成授权，不触发模型。回应丢失后最多读取原工程，不自动再POST。

`public/input-group-membership.js`实现勾选、预览、确认与本机回执恢复。`public/canvas-edit-merge.js`将提交时快照、请求期间较新本地编辑和已保存结果进行三方合并；冲突保留本地值供检查。`public/app.js`将旧自动保存与新拖动保存排序，防止等待中的自动保存覆盖最终位置；失败撤回位置时保留请求期间新增文字与节点。

跨类型共享成员保留语义组；原导入附加视觉框仅在精确匹配旧成员时跟随，独立视觉组不被改写。重叠/清空时将显示框样式保存在groupDisplayState，恢复可显示时取回颜色、折叠和编号。原生导入保留全部语义组，不因辅助视觉框重叠拒绝有效共享组。

档案白名单补上原生组w/h、隐藏显示框状态和成员回执的已知字段，避免完整任务档案因过滤这些字段而与工程备份不一致。秘密字段、未知任务/字段、损坏档案及不一致快照检查继续有效。
