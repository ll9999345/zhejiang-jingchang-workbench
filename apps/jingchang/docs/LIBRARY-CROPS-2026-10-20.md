# 素材库批量居中裁剪 · 0.99.16

入口：资产 → 素材库管理 → 媒体分组 → 勾选图片 → 批量居中裁剪。与普通画布的单张自由裁剪分开；本项把选中的素材库图片逐张居中裁成正方形，保存独立 PNG，原条目和原文件保留。

## 使用

1. 在素材库媒体分组选择图片；跨页选择最多200个不同条目。非图片、回收内容、缺失原文件会明确拒绝，先调整选择，不静默略过。
2. 点击“批量居中裁剪”，保存位置默认“各自原分组”；可以选择另一个有效媒体分组。点击检查后看到原图、原尺寸、正方形尺寸及左/上裁剪坐标。
3. 确认图片和目标分组，再点击“开始本机裁剪”。只使用本机FFmpeg，不需要API Key，不调用AI，不上传。首次检查及开始前复验可能需要等待。
4. 原图保留，新条目命名“原名称_crop.png”。可以下载实际 PNG，也可以“将完成副本加入当前项目”；不会自动替换画布节点。重复加入识别同一副本，不重复添加或覆盖后续编辑。
5. “完成当前图片后停止”会先保存当前本机图片，再停止后续项，不声称立即终止编码。关闭窗口不停止任务。重新进入素材库管理的“裁剪记录”可查看。
6. 中断或停止后，先读原批次，勾选继续本批未完成项，再明确继续。已完成副本编号保持；已持久化但尚未发布的副本沿用原结果，不重新编码。若原图已变、条目回收或目标分组失效，先恢复原范围或以新批次重新检查。

普通单张任意区域裁剪仍保留。GIF只取第一帧，结果不保留动画。方图也另存独立副本。按原像素居中，不自动旋转或缩放，不新增EXIF朝向纠正语义。新副本不继承原AI分类、描述或真人素材注册URI；旧资料保留在原图。

## 保存与恢复

批次位于 `data/jobs/<requestId>.json`，种类 `library-crop`。快照包含原条目/文件、原字节SHA-256、尺寸、确定裁剪范围及目标分组；逐项记录状态、尝试数、固定库条目编号和输出校验。图片位于 `data/assets/`，分组文件副本位于原有 `data/asset-catalog/libraries/`。未完成文件和原编码输出保留，不自动清理。

只读GET和页面重开不会再次裁剪、自动发布或改写原记录。运行中的批次只在最终记录持久化完成后显示终态；读取旧运行状态不会覆盖最新完成状态。启动恢复把遗留运行批次标为中断，不自动处理。

当前工程和素材库整库备份继续按原语义携带已加入/已保存的图片及组织关系。完整 `.jhistory` 另含该项目原收藏与裁剪任务、全部相关原图和结果；迁移为新工程后旧任务只读，活动任务为空，不续跑。归档校验原图和结果文件的SHA/大小/类型与任务对应关系。原图或副本被移走时不能声称完整归档。

## API

- `POST /api/library-crops/preview`：`{projectId, ids:[素材库条目编号], revision, libraryId?, folderId?}`。不提供目标时各自原分组；同时提供库/分组时保存到该媒体分组。返回 `plan/fingerprint/revision/localOnly`，不创建任务。
- `POST /api/library-crops`：同上加 `{requestId, fingerprint, consent:true}`。再次校验，202返回任务。相同编号/原指纹只读取原任务，不创建新批。检查失败不创建任务。
- `GET /api/library-crops?projectId=…`、`GET /api/library-crops/:id?projectId=…`：只读原记录。项目不匹配拒绝。
- `POST /api/library-crops/:id/cancel`：`{projectId}`，完成当前项后停止。
- `POST /api/library-crops/:id/resume`：`{projectId, consent:true}`，只继续原范围的未完成项。
- `POST /api/library-crops/:id/apply`：`{projectId, revision}`，终态的完成副本加入项目；有版本保护与重复识别。
- 通用任务取消同样可停止裁剪；通用resume拒绝，要求从专用记录确认范围。

运行能力标记 `libraryCrops:true`。网页只在后端声明支持时展示新增入口，防止静态文件与旧运行服务短暂不同步时暴露不可用操作。

## 范围和验收

每批1–200条，工作区同一时间一批；单图片≤150MiB、解码后≤16,777,216像素；PNG结果≤80MiB。PNG/JPEG/WebP/GIF/AVIF/BMP按已有媒体解码器接受，实际可用性受本机FFmpeg编译与文件编码影响。本轮实际验证PNG、透明方图、JPEG、WebP、两帧GIF和BMP；未把AVIF各编码组合或200张最大批次称作已实测。

真实FFmpeg逐像素核对奇数宽高的居中范围与透明通道，停止/继续、输出已保存时实际SIGKILL、重启、固定编号、长请求编号、终态收尾、旧读取竞争、完整归档和篡改拒绝均有隔离验证。浏览器使用已有Chrome for Testing150，含390px、键盘、低动态及静态模拟；实体手机、旧机GPU、Windows/WSL和日常Chrome155未在本轮验收。新依赖安装0，云端调用/付费调用/第三方素材上传0。
