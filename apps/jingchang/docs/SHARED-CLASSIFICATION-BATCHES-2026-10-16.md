# 2026-10-16 · 共享文件夹本批图片分类

本轮是镜场自有实现的增量，不调用参考产品的Agent。功能参照用户指定 Infinite Canvas 固定提交 `67f49e4b9a0ac090bad1f5bd62ae385f8fb5394e`，本地已保存源 `main.py.reference` 16924–16948 行：每批最多200项、图片导入后分类。参考源码未作为服务器执行，来源和许可沿用项目既有第三方说明。

## 怎么使用

1. 资产 → 共享文件夹，按原流程选择媒体并导入本机副本；导入本身不发送图片。
2. 在已结束的导入记录点击“批量图片分类 / 原记录”。核对缩略图、名称、字节数，勾选本次图片；视频、音频、GIF、BMP或超过10MB的图片会跳过，不伪装成已分类。
3. 选择已登记、支持图片输入的OpenAI兼容对话模型，核对服务地址；提供本次凭据，填写整批总预算与币种，勾选同意后执行。补充说明可选。
4. 每张图片有固定请求编号，串行发送，各自保留原收据和分类结果。进度来自收据，不模拟完成百分比。一个请求失败或结果不确定，停止后续项。
5. “停止后续图片”保留已完成结果；已经发送的请求不能撤回，可能产生费用。未知结果显示“结果与费用待核对”，不能继续本批。
6. 明确拒绝、发送前停止或进程在未发送时中断后，若仍有未发送项，可以点击“重新确认并继续未发送项”。重新提供凭据及相同补充说明，沿用原图片、模型、服务、次数和总预算；不重试已提交项。
7. 关闭再打开、刷新页面或服务重启，只读取原记录，不自动续跑。完成分类通常已经回填素材信息；若本机回填中断，用“核对完成分类回填（仅本机）”，再次核对原图指纹后恢复本机标签，不调用模型。
8. 导出“全部留痕”`.jhistory`时，保留原导入记录、批次清单及逐图原收据。导入为新工程与只读档案；不创建活动批次，不复制共享文件夹访问许可、密钥或重新发送同意。`.jingchang`工程包仍不含任务历史。

预算是授权记录，不是供应商硬限额。整批总预算平均分配为逐图授权，继续时不再增加总次数或总预算。真实收费以平台为准；用户尚未提供具体服务、预算及发送范围，本轮没有向第三方发送素材或调用付费生成。

## 服务与持久化

新增 `lib/classification-batches.mjs`、`public/classification-batches.js` 与配套CSS。服务复用现有单图分类器，向分类器传入确认过的媒体/服务/提示词摘要；发送前检查实际请求匹配。初次确认读取整批，实际执行只读取当前图片，不为每张重复读取全部200图。

| 接口 | 行为 |
| --- | --- |
| `POST /api/classification-batches/preview` | 本机预检 `{projectId,sourceImportId,assetIds?}`，返回支持图片、跳过项和`planDigest`，不访问模型 |
| `POST /api/classification-batches` | 明确确认后创建，返回202；固定`requestId`、`assetIds`、预检摘要、平台、模型、补充说明、凭据、同意与整批授权 |
| `GET /api/classification-batches?projectId=&sourceImportId=` | 本机批次记录；后者可选 |
| `GET /api/classification-batches/:id?projectId=` | 原范围、逐图原收据、计数和实际状态 |
| `POST /api/classification-batches/:id/cancel` | `{projectId}`，停止后续图片；在途请求保守记为不确定 |
| `POST /api/classification-batches/:id/resume` | 原范围重新确认，额外`resumeUnsent:true`；只处理没有原收据的图片 |
| `POST /api/classification-batches/:id/apply` | `{projectId}`，核对完成收据与当前原图后本机回填；不访问模型 |

发送请求的`authorization`必须为 `{origin,model,sendImage:true,requestLimit:N,budget,currency,consent:true}`，其中N等于本批原图片数。本机环回服务允许预算0；远程服务须正预算。每次实际发送均保留单图requestLimit=1，budget=原总预算/N。凭据支持手填或沿用既有、限定用途的本机喵喵来源；选择本机来源仍须本次`credentialConsent:true`。凭据与补充说明原文仅驻留执行闭包，结束即清理，不写入批次存储。

`data/classification-batches/`使用不可覆盖的批次清单、编号执行占位及停止/结束标记。完整字节同步到盘后，以不可覆盖链接发布；不同实际Node进程竞争相同批次/执行编号只能有一方取得执行。逐图结果仍在`data/asset-classification-tasks/`，不可覆盖终态为准。单图记录也改为完整写入后发布，避免轮询看到初次创建的半份JSON；读取时允许有限次数处理正常原子替换，不忽略损坏数据或链接。

批次存储不进入通用generation jobs，避免被误当作视频任务恢复。专用窗口显示真实状态；本轮没有声称任务岛已经增加独立批次聚合。全部留痕的附属收据新增`source:classification-batches`，严格校验原范围摘要、逐图编号、原图片指纹、原总预算、逐图预算和状态对应关系；活动批次阻断归档。源共享导入任务采用限定字段契约，保留复制结果和相对文件名，不扩大其它任务的字段白名单。归档的`classificationBatches`数量由清单推导。
