# 图片分类记录随全部留痕迁移（2026-10-16，同日后续）

本轮补齐上一个阶段未完成的分类收据迁移。`.jhistory` 现在保留分类的原请求编号、服务与模型、图片指纹、提示词摘要、授权预算、四类终态和完整分类标签；恢复后留在只读档案，不写入运行中的分类任务或生成任务。当前工程的 `.jingchang` 备份仍只带工程与素材，不包含任务历史；需要迁移请求记录时使用“全部留痕”。整体参考功能整合尚未完成，付费调用继续暂停。

## 使用方法

1. 保存工程，点顶栏“版本历史”→“导出全部留痕”。预览现在单列“图片分类记录”数量。等待发送或正在发送的分类尚未结束时会阻止归档，先完成或停止后再导出。
2. 在另一台电脑或独立工作区，从“版本历史”→“导入留痕档案”选择 `.jhistory`。检查完整性和素材校验，确认后创建新工程，原工程保留。
3. 打开新工程的“版本历史”→“只读档案”→“查看”→“图片分类原请求”。可查看原服务、模型、时间、图片 SHA-256、授权范围与原结果，也可下载原分类图片。
4. “结果待核对”仍保持不确定，不会变成成功或未发送。只读档案没有重新分类、恢复发送或取消上游的按钮；如需新一次分类，回到素材页另行明确授权。

原任务记录与当前工程资产的编号映射分开保存；分类标签随当前资产恢复，原请求仍保留源素材编号。已从当前工程移走的历史素材只保存在档案中，不自动重新加入当前画布。

## 实现与不变量

- 读取 `data/asset-classification-tasks/` 的不可覆盖 `.terminal` 终态；存在时优先于可能较旧的 `.json`。归档不修改原收据，也不触发模型、凭据解析或任务恢复。
- 明确归属当前工程的记录全部纳入；无工程归属的旧全局记录，仅随工程实际引用的图片纳入；明确属于其它工程的记录不混入。
- 分类结果使用独立的有界结构校验，保留 `categories`、`flat`、自定义维度、标签及原时间，不靠通用字段过滤器悄悄丢字段。
- 密钥、原凭据来源同意、进程身份和执行绑定不迁移。预算、同意与单次图片范围作为原授权记录保存，不形成在新工程重新发送的权限。
- 分类图片必须与原请求的 SHA、大小和类型一致。不一致时标记不完整且禁止完整恢复；活跃分类阻止导出。归档期间原收据或目录变化会阻止生成可下载的就绪文件。
- 分类记录只进入档案 `auxiliaryReceipts`，不进入 `jobs` 或目标 `asset-classification-tasks`。恢复后仍不可执行，后台重启也不会重发。
- API 导出、预览及只读记录新增 `classifications` 数量；只读数量从有效清单推导，单独改数量会被拒绝。旧档案没有分类字段时兼容显示 0。

核心文件：[portable 分类结构](../lib/asset-classification-history.mjs)、[归档服务](../lib/task-history-archive.mjs)、[快照校验](../lib/task-history-schema.mjs)、[只读分类视图](../public/classification-history-view.js)、[原归档入口](../public/task-history-archive.js)。没有接入第三方 Agent。
