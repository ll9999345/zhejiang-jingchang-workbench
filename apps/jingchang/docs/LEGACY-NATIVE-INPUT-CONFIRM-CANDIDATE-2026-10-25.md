# 旧任务明确确认后续跑 · 候选阶段二 · 2026-10-25

本轮补齐可唯一还原的一类旧任务操作闭环，状态为**范围内验证通过，未正式发布**，整体整合目标仍 active。正式镜场 4768 为 0.99.22 / PID 85041，主工作台 4750 为 PID 29280；只读健康核对，未重载。共享源码归档时为 0.99.23-dev.8，本轮未修改版本/lock 元数据，保留同期其他工作的生命周期、手势等修改。18 份相关测试不能当作整个 dev.8 的发布验收。

## 入口及实际变化

任务中心 → 原中断/停止画布任务 → **核对旧任务素材** → 查看原范围和重建范围 → 勾选并确认 → **继续原画布任务**。确认不启动任务，续跑仍使用原服务、模型、发送范围、次数和预算检查。本轮实际使用自建本机图片与环回协议消费者，没有真实模型推理或第三方上传。

例如旧记录仅写“2 份”，原含义为生产者第 1、2 份；已保存循环需要第 3、4 份。现在先展示差别，服务器重读原任务并推导选择，不能由客户端任意提交新序号。明确确认后只追加决策，执行副本使用确认后的范围；原步骤 `nativeReferences` 和快照不改写。不能可靠还原的旧逐轮映射、重复同范围选择或缺快照仍明确不能确认。

## 实现依据

- `native-input-review-proof.mjs` 提供规范化 SHA-256、严格限长/限字段的追加式凭据。绑定原任务、步骤/细项、接口命令、循环/分支、媒体版本、上游选择结构与绑定配置；不包含进度、状态、子编号等运行噪声。
- 已完成上游以真实产物列表核对原生产序号，不把 `workflow.count` 当作返回数量。已知产物的编号/顺序另绑定输出指纹；尚未生成时明确确认未来原序号，待实际产物出现后重新检查，缺项不会改选第一张。不能将用户确认理解为绕过接口原有数量、媒体类型、来源及费用限制。
- `native-input-review-service.mjs` 在原任务锁内预览/确认，最多 128 条凭据、每条最多 512 项选择；同令牌重复点击幂等。预览只读，确认只追加 `nativeInputReviews`。过期范围返回专用 409；只读导入/活动项目/不适用任务拒绝。
- 原任务 GET/列表的链接恢复在同一锁内重新读取最新文件，避免使用旧副本覆盖决定。已有原子任务优先按原编号或确定性请求编号查询，不自动重发。
- runner 仅为存在相应确认的步骤创建执行副本，并保留 `nativeInputReviewApplied` 留痕；新计划继续走原严格解析器。修复回归中发现的早期检查误占新计划数量检查路径的问题，没有通过放宽旧测试来掩盖。
- 液态任务窗口和原授权表单显示人类序号 3、4；授权表单仅使用展示副本，读密钥仍由原控件处理。本次密钥不写入任务、历史或日志。确认前后与单独续跑分开显示。
- 历史导出/只读导入严格保留原记录和已执行确认；未知字段、篡改指纹和跨任务复用拒绝。导入不能赋予新生成权利。
