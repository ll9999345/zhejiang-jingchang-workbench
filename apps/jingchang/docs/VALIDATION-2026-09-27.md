版本 0.3.0。本轮补齐 API 平台/模型设置、兼容图片接口的文生图与参考图编辑、上游文字传递、请求授权记录、任务回收、本机诊断及可恢复项目回收站。没有调用 LibTV 或 RunningHub 的 Agent。

## 验证结果

- `npm test`：44/44 通过；语法检查通过。
- 图片 API 浏览器验收：平台保存和模型拉取、图片能力配置、上游文字传递、尺寸/质量、文生图、参考图上传与 multipart 编辑、生成结果加入项目、密钥不落盘、诊断、手机布局、项目移入回收站与恢复。最终证据：`artifacts/image-api-qa-1790441431654/result.json`。
- 原有工作台浏览器回归通过：提示词、分组/复制/对齐、素材复用、本机配置、ComfyUI 工作流、生成任务回收、Agent 计划应用及手机布局。证据：`artifacts/studio-qa-1790441041408/`。
- 核心浏览器回归通过：项目保存、剧本/分镜、真实本机 FFmpeg 合成和 MP4 下载、版本冲突、跨源拒绝、刷新恢复。证据：`artifacts/qa-1790441042332/`。
- 并发保护：12 个相同 requestId 同时提交，只生成 1 个任务和 1 次模型请求；不同请求在同一项目生成期间拒绝；失败校验释放提交锁。
- 安全检查：公网目标拒绝私网和特殊用途 IPv6；DNS 解析后固定已检查的目标；图片下载不携带 API Key；不跟随重定向。提交后 5xx、2xx 无效响应或图片下载失败标记结果不确定，不自动重试。
- 确认没有运行中的任务后，替换了旧版 0.2 本地服务。4768 健康接口返回 0.3.0；Chrome 实际页面已展示 API 平台与模型设置。

## 实际验证边界

图片模型、语言模型与 ComfyUI 均使用 localhost 模拟服务，没有使用真实密钥，没有云端生成或第三方素材上传，没有费用。真实本机视频编码已运行。预算只是一次调用的授权记录，不是供应商扣费硬上限。

图片接口实现不等于全部平台协议兼容：云端对话、ModelScope 异步、APIMart、Gemini 原生、RunningHub 应用/工作流、方舟视频仍待实现，完整差异见 `FEATURES.md` 和 `API.md`。原站登录后的全部功能仍未逐一验收，因此不宣称一比一复刻完成。

浏览器测试使用独立数据目录，未将用户项目作为测试数据。回收站不删除文件，也不自动清空。
