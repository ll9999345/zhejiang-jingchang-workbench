# 图片分类原请求收据与重启恢复（2026-10-16）

同日后续：分类原请求现已能随`.jhistory`迁移并只读查看，见[新阶段验收](CLASSIFICATION-HISTORY-2026-10-16.md)。下文“迁移未完成”为上一个阶段留档状态；`.jingchang`工程-only备份仍不包含任务历史。

本轮补齐的是图片智能分类的本机留痕、原编号查询和中断保护。此前仅靠进程内记录，重启后难以确认图片是否已发送；现在发送前保存原请求绑定，重启后先读取旧收据。结果不确定时停止在原记录，不自动重发图片。

这是指定功能的实现与验收记录，不代表全部参考项目功能完成。参考基准保持 Infinite Canvas 固定提交 `67f49e4b9a0ac090bad1f5bd62ae385f8fb5394e`；未调用参考项目的 Agent。付费生成继续暂停。

## 用户怎么用

1. 在统一入口打开工程，进入素材页。PNG、JPEG、WebP 图片卡片可点“智能分类”；已有分类时显示“重新分类”。素材卡片、“管理素材”窗口和分类表单均有“分类记录”入口。
2. 新一次分类仍需选择支持图片输入的对话模型、核对服务地址、图片和补充说明，并明确同意最多发送这一张图片一次。云服务还需填写本次预算和币种；本机喵喵凭据选择仍需原有独立授权。
3. 提交后手填密钥立即从表单清空，重复点击回到同一请求的记录。正常完成会显示分类摘要、分类标签与已保存的收据。
4. 响应丢失、失败或服务重启后，从“分类记录”读取原编号。列表展示服务、模型、图片校验、授权范围、预算记录、创建时间、状态和已保存结果；查询与刷新不会调用模型。
5. 只有等待发送或正在发送的记录提供“停止本次分类”。发送前停止会保留“已停止”；发送后停止只能结束本机等待，显示“提交结果待核对”，不能撤回上游请求或保证不扣费。
6. 遇到“提交结果待核对”，先核对平台任务和账单。本窗口没有恢复发送或自动重试入口；新一轮分类必须重新确认服务、模型和预算。

## 本轮具体行为

| 情况 | 当前处理 | 用户收益与边界 |
| --- | --- | --- |
| 发送前 | 输入、模型与授权校验通过后，独占创建 `queued` 收据并解析本次凭据；再将 `sending` 和发送意图写入磁盘，最后调用上游 | 无有效同意时不读取凭据或创建收据；断电或强杀后保留发送阶段依据，发送意图不是上游已接受的证明 |
| 同编号再次到达 | 图片实际字节校验、项目、平台及服务地址、协议、模型、提示词摘要、同意与预算等绑定必须一致 | 已完成结果可按原编号复用，只补必要的本机回填，不再提交模型；绑定变化返回拒绝 |
| 同进程并发或两个 Node 进程并发 | 进程内共享正在处理的请求；磁盘独占创建和不可覆盖的终态标记协调跨进程竞争 | 同一编号不会因双击或进程并存再次发送；停止后迟到成功不能把终态改回执行中 |
| 服务中断 | 原拥有者进程已退出时，未发送的 `queued` 转为 `cancelled`，进入发送阶段的 `sending` 转为 `uncertain` | 不猜测失败或成功，不自动补发；仍活着的拥有者不会被另一进程擅自认定已中断 |
| 明确上游拒绝 | 保存脱敏失败说明及允许公开的状态信息，原编号不自动重试 | 原始异常、密钥和完整请求正文不进入收据 |
| 发送后响应不完整、丢失或停止 | 保留 `uncertain`，提示核对结果与费用 | “停止”只管理本机等待，不把未知结果当作未收费 |
| 请求期间图片改变 | 比较返回前的实际字节校验，拒绝将旧图片的分类写给新图片 | 保留素材和原请求信息，不静默覆盖新内容 |

实现文件为 [分类服务](../lib/asset-classification.mjs)、[磁盘收据存储](../lib/asset-classification-receipts.mjs)、[专用记录弹窗](../public/asset-classification-tasks.js) 与 [素材页入口](../public/app.js)。Node.js 文件接口负责独占创建、文件同步和终态提交；SHA-256 用于绑定实际图片与配置摘要。收据不保存 API Key、图片 data URL、完整提示词正文或原始上游异常；显示结果经过限制和脱敏。

预算及同意没有被新收据机制替代。原有服务地址、模型、单张发送范围、最多一次请求、币种、预算和凭据来源授权仍逐项检查。预算是授权记录，不能强制限制供应商实际扣费；本次本机验收不使用真实云密钥或真实计费。

## 服务接口

| 接口 | 请求与作用 | 是否发送模型请求 |
| --- | --- | --- |
| `GET /api/asset-classification-tasks` | 返回本机分类收据数组，可选 `assetId`、`projectId` 筛选；无效编号拒绝 | 否 |
| `GET /api/asset-classification-tasks/:id` | 读取指定原编号，未找到返回 404；损坏记录拒绝继续发送 | 否 |
| `POST /api/asset-classification-tasks/:id/cancel` | JSON 请求体 `{}`；等待发送转已停止，发送阶段转结果待核对；终态保持 | 否，仅停止本机处理 |
| `POST /api/assets/:assetId/classify` | 既有提交接口，新增持久化同编号绑定；仍需原有授权与有效输入 | 仅新编号且准入通过时最多一次；原编号不自动重发 |

没有新增分类 `resume` 接口。仅凭“查询成功”不能声称上游任务已接受或费用已结清。
